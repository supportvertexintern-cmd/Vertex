# Documentation rules

- Preserve existing documents unless a change is requested. Verify technical claims against code and active configuration before presenting them as current.
- Keep historical records clearly labeled as historical. Do not remove historical business decisions solely because their implementation has changed.
- Do not treat `PRD.md`, `ROLES_AND_PERMISSIONS_REVIEW.md`, or `PLATFORM_ARCHITECTURE.md` as fully verified current specifications; see the source authority register.
- Record unavailable originals as unavailable only when the user has confirmed that status. Do not recreate missing approved documents from memory.
- When updating an inventory or authority register, state what was checked and distinguish “not found” from “unavailable.”
